# 03 加密与激活

本章规范 API Key 的本地加密存储与离线激活体系。目标：明文永不落盘，换机拷贝即失效，纯离线可用。

## 3.1 设计原则

1. **KEK 只驻内存**：每次启动时派生，用后清零，不落盘、不进 Env、不进日志。
2. **Env 只存非秘密因子**：仅存 `salt / 版本 / 派生密钥引用`，绝不存 KEK 与 API Key 明文。
3. **机器绑定优先**：TPM 优先，无 TPM 才降级 DPAPI。
4. **前端永远只见掩码**：如 `sk-9a~~~~7f3`，全量明文仅在后端内存中短暂存在。
5. **纯离线可用**：后端一次性签发长期派生密钥，用户以激活文件/激活码形式导入，之后无需联网。

## 3.2 密钥层次图

```text
后端长期派生密钥（离线激活导入） --+
TPM密封机器码（32字节随机码）    --+--> KEK派生（PBKDF2 20万次） --AES-256-GCM--> keys_encrypted.db
KEYPOOL_SALT（Env/.env）        --+
KEY_VERSION（Env）               --> DB版本
KEK（仅内存）                    --> 内存调度层解密调用 --> 前端掩码展示
```

派生公式（规范锁定）：

`KEK = PBKDF2( 后端长期派生密钥 || TPM密封机器码 || salt, 200000次 )`

落盘统一为 `AES-256-GCM(KEK)`，每条记录独立 nonce，篡改即解密失败。

## 3.3 激活流程

> 本机自签发（单机版落实）：没有远端签发方，首次由后端在用户点击“激活”时本地生成派生密钥并密封，语义与“一机一签”一致。

**一键激活（设置页 → 持久化卡片，或 `POST /api/keys/activate`）：**

1. 先试无损解锁：密封 + 派生密钥完好即直接恢复，不碰任何文件；
2. 否则重签：生成派生密钥 → 写本机 `.env`（`FREEAI_DERIVED_KEY/_ID/_SALT`）→ 密封机器码（TPM 优先，无则 DPAPI）→ 用新 KEK 探测旧库，解不开则归档为 `.bak-时间戳`（不静默覆盖）→ 建库 → 重建持久池 → 把内存 Key 迁入（用量归零）。
3. 状态查询：`GET /api/keys/persist-status`（是否激活/写透/需重激活/DB/内存数）；未激活时设置页顶栏告警，`force: true` 可强制重签。

**未激活后果：** 密钥只在内存，重启后端即丢失（且之前录的需重录一次）；激活后录入的 Key 写透加密盘，重启自动恢复。**后端必须从仓库根启动**（`python -m uvicorn backend.main:app …`），否则 keypool 接不上加密基座，激活接口会明确报 500 而不是假装成功。

**首次激活：**

1. 后端签发 `DERIVED_KEY + DERIVED_KEY_ID + SALT`（激活包，一机一签）。
2. 用户本机导入激活包 → 生成 32 字节随机机器码 → TPM 密封（或 DPAPI 保护）。
3. 派生 KEK → 创建空 `keys_encrypted.db` → 状态显示 `TPM锁定` / `DPAPI兜底`。

**重装 / 解封失败：**

1. 启动检测到 DB 存在但 KEK 解密失败（TPM NV 丢失 / sealed blob 损坏 / 用户 Profile 变更）。
2. 锁定密钥池，禁止写入，提示 `重新激活`。
3. 用户重新导入原激活包或申请新激活包 → 重新密封机器码 → 重建 KEK → 若 DB 可解则恢复，否则清空重建。

**换机：**

1. 直接拷贝 `keys_encrypted.db` 到别机必然解密失败（机器码不同）。
2. 必须在新机重新走首次激活，老机数据不迁移明文，只允许重新录入 Key。

吊销说明：纯离线下无法实时吊销。后端吊销名单只能在下次联网/下次签发时生效，本章不承诺离线吊销能力，需在产品文档中明示。

## 3.4 TPM 与 DPAPI 路径对比

| 维度 | TPM 优先路径 | DPAPI 兜底路径 |
|---|---|---|
| 存储对象 | 32 字节随机机器码，经 TBS / TPM2.0 NV 或 sealed blob 密封 | 32 字节随机机器码，经 `CryptProtectData` 加密存本地文件 |
| 绑定强度 | 强绑定主板+PCR/owner，拷贝到别机不可解 | 绑定 Windows 用户 Profile，换机不可解，重装用户丢失即不可解 |
| 离线可用 | 可 | 可 |
| 前端显示 | `TPM锁定` | `DPAPI兜底` |
| 失败处置 | 统一提示重新激活 | 同左 |
| 适用条件 | Win10/11 + TPM2.0 可用 | 无 TPM / TPM 被禁用 / 虚拟机 |

无任何保护即为 `未加密` 状态，仅允许开发调试，正式版禁止写入明文 Key。

## 3.5 Env 变量规范

| 变量 | 内容 | 能否进 git |
|---|---|---|
| `FREEAI_KEY_VERSION` | 密钥库版本号，如 `v1` | 可进，默认值随代码发布 |
| `FREEAI_KEYPOOL_SALT` | PBKDF2 salt（Base64，非秘密） | 模板可进，生产实例建议 per-激活覆盖 |
| `FREEAI_DERIVED_KEY_ID` | 后端长期派生密钥引用 ID | 绝不进，仅存本地 `.env` / 用户配置 |
| `FREEAI_DERIVED_KEY` | 后端长期派生密钥本体 | 绝不进，仅激活导入 |
| `FREEAI_KEY_DB_PATH` | 默认 `%APPDATA%/free-ai-video/keys_encrypted.db` | 可进 |

红线：KEK、API Key 明文、TPM 机器码明文绝不进 Env、`.env`、git、日志与崩溃转储。

## 3.6 轮换与备份恢复

轮换：

1. 后端签发新 `DERIVED_KEY`（版本号+1）→ 本机导入。
2. 用老 KEK 解密全库 → 用新 KEK 重加密写回 → 原子替换 DB → 老密钥内存清零。
3. 轮换期间禁止并发写入，失败则回滚到老 DB。

备份恢复：

1. 只备份密文 DB + `KEY_VERSION + SALT + DERIVED_KEY_ID`，不备份 KEK。
2. 同机恢复：重装后先重新激活（恢复密封机器码），再用备份 DB 解密。
3. 异机恢复：不允许直接恢复 DB，仅允许迁移激活资格后重新录入。

## 3.7 威胁模型与缓解

| 威胁 | 后果 | 缓解（本章规范） |
|---|---|---|
| 明文落盘 | 偷文件即泄 Key | 明文永不落盘，仅 `AES-256-GCM(KEK)` 落盘 |
| 文件拷贝到别机 | 窃取 DB 异地解密 | KEK 混入 TPM 机器码，换机 KEK 不同，GCM 校验失败 |
| 机器码伪造 | 伪造 Env 绕过绑定 | 机器码不进 Env，TPM 密封/DPAPI `CurrentUser` 保护，伪造者拿不到密封值 |
| 内存 dump | 进程转储扫到明文/KEK | KEK/明文最小驻留、用后清零、不记录日志；仅接受降低风险，不承诺绝对防 dump |

## 3.8 Windows 实现要点

1. **TPM 可用性检测**：启动时按序检测 TBS 服务 → TPM2.0 → NV/sealed 读写自检，任一步失败即降级 DPAPI，并上报前端状态，不静默回退。
2. **DPAPI 规范**：必须 `scope=CurrentUser`，`LocalMachine` 禁用；熵值与 `DERIVED_KEY_ID` 绑定，避免同机多用户串解。
3. **路径与权限**：DB 固定 `%APPDATA%/free-ai-video/keys_encrypted.db`，目录仅当前用户 ACL，失败解锁时锁定写入口。
4. **状态可观测**：托盘/设置页常显 `TPM锁定 / DPAPI兜底 / 未加密`，降级与解封失败必须弹窗引导重新激活。

## 3.9 验收清单

- [ ] 断电/重启后无需联网即可解密，KEK 重派生成功
- [ ] DB 拷贝到别机解密失败并提示重新激活
- [ ] 无 TPM 机器正确显示 `DPAPI兜底`，有 TPM 显示 `TPM锁定`
- [ ] Env/仓库中搜不到 KEK、API Key 明文、机器码明文
- [ ] 前端抓包与日志中仅见掩码，无全量 Key
- [ ] 重装/删密封值后触发重新激活流程，老 DB 不被误覆盖
- [ ] DPAPI 调用均为 `CurrentUser`，DB 目录权限仅当前用户
